# Personal 与 DSH 的分工

Personal 的四个包共同提供业务功能；DSH 提供 Agent 循环、原生聊天、模型调用、工具调用、审批、工作区、凭据、会话和存储设施。安装器通过官方 `dsh` 配置启动应用，不建立第二套 Agent 循环或聊天状态。

任务、对话归档、代码归档、复盘和调查记录继续使用原有存储域及记录 ID。包名前缀改为 `@xrunmasterx` 不改变数据归属。新增加的 `personal_plugin_records` 仅保存 Personal 的原生会话关联及任务润色请求/结果审计，避免要求官方 Session 核心识别插件专有的必需事件。

旧会话的 Personal 元数据保留原类型、数据、序号及时间戳，仅在复制出来的数据中增加 `ignorable: true`。迁移拒绝未知的 Personal 事件和改变模型历史表面的事件。原生问答不删除，不改写。迁移逐个解析 Zstandard 帧，不使用只读取首帧的解压结果替换整个会话文件。

模型可见的任务信息仍通过官方系统提示词机制进入请求日志；任务关联表负责恢复关联，不代替模型请求日志。外部 Codex/Cursor 历史及辅助分析断点继续由 Personal 的归档域拥有。

本版本固定官方 DSH 0.1.6-alpha.1，并维护两份显式补丁：欢迎文案两行替换；JSON 记录读取限制并发、明确报告句柄耗尽。后者由大数据副本启动时实际出现的 EMFILE 错误触发，并有模拟句柄上限的确定性测试。两者都不改变会话格式或 Agent 行为。构建器的 Remote 识别适配只生成临时构建工具。

升级 DSH 时先更新兼容版本及适配、在干净安装中构建和测试，再用停机数据副本验证历史读取。业务代码更新与底座升级分别验证，原始数据目录保留作回退依据。当前不承诺任意外部 CLI 或 0.2 版本兼容。
